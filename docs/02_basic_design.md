## 1. システム概要

日々の支出・収入をカテゴリ別に記録・管理するシンプルなデスクトップアプリケーション。収支の一覧表示、CSVファイルによるデータの保存・読込、カテゴリ別／年別／月別の統計表示（グラフ・表）を提供する。

## 2. 対象ユーザー・動作環境

| 項目 | 内容 |
|---|---|
| 想定ユーザー | 個人の家計管理を行う利用者（単一ユーザー・ローカル利用を想定、マルチユーザー機能なし） |
| OS | Windows |
| 実行環境 | Python 3.10以上（`pip install -e .` でインストール後、`python -m kakeibo_app` で起動） |
| 画面構成 | メイン画面（常時1枚）＋統計画面（モーダルで都度開く） |
| ウィンドウサイズ | メイン画面: 820×560（起動時。以降リサイズ可、最小サイズは構築後の要求サイズ） / 統計画面: 900×600 |

| F06 | 合計金額表示 | 支出合計・収入合計・ネット残高（収入−支出）を表示する | メイン画面 |

## 4. 画面一覧・画面遷移

| 画面ID | 画面名 | 種別 | 実装クラス |
|---|---|---|---|
| S01 | メイン画面 | メインウィンドウ（`tk.Tk`） | `transaction_entry.view.MainWindow` |
| S02 | 統計画面 | モーダルウィンドウ（`tk.Toplevel`） | `summary.view.SummaryWindow` |

```
[アプリ起動]
     │
     ▼
┌─────────────┐   「統計」ボタン click    ┌─────────────────┐
│ S01 メイン画面 │ ───────────────────────▶ │ S02 統計画面      │
│ （常時表示）    │                          │（モーダル・一時表示）│
│                │ ◀─────────────────────── │                  │
└─────────────┘      ウィンドウを閉じる      └─────────────────┘
```

- 統計画面はモーダル（`transient` + `grab_set`）であり、開いている間はメイン画面を操作できない。
- 統計画面はメイン画面のデータが1件も無い場合は開けない（「表示するデータがありません」と案内）。
- 統計画面はメイン画面のデータの **スナップショット** を保持するのみで、開いた後にメイン画面側でデータを変更しても統計画面には反映されない。

| 領域 | 構成要素 | 備考 |

## 6. データ項目定義

業務データの正準表現は `Transaction`（`shared/models.py`）。

| 項目名 | 内部フィールド | 型 | 必須 | 取り得る値／桁数 | 備考 |
|---|---|---|:---:|---|---|
| 金額 | `amount` | `int` | ○ | 1以上の整数（上限なし） | 0・負数・小数は不可 |
| 日付 | `date` | `datetime.date` | ○ | 実在する日付 | 入力形式は`YYYY/MM/DD`または`YYYY/M/D` |
| 種類 | `transaction_type` | `Literal["支出","収入"]` | ○ | 「支出」または「収入」 | |
| カテゴリ | `category` | `str` | ○ | 種類ごとに定義された一覧（7.3参照） | 一覧外の値は不可（自由入力不可） |
| メモ | `memo` | `str` | - | 任意の文字列（既定は空文字） | 前後の空白は除去 |

`Transaction`はNamedTupleによる不変レコードであり、内部ID（連番）は`Transaction`自体ではなく`TransactionRepository`側が管理する（詳細設計書参照）。

## 7. 業務ルール概要

詳細な検証ルール・正規表現・エラーコードは「詳細設計書」を参照。ここでは概要のみ示す。

### 7.1 金額の入力ルール

- 1以上の整数のみ有効。0・負数・小数はエラー。
- 先頭に`¥`を許可。
- 3桁区切りカンマは正しい位置の場合のみ有効。
- 全角数字は自動的に半角として扱う。

### 7.2 日付の入力ルール

- `YYYY/MM/DD`（ゼロ埋めありなし両対応）。
- 区切り文字は`/`のみ（`-`区切りは不可）。
- 実在する日付のみ有効（例: 2/30は不可）。

### 7.3 カテゴリ一覧

| 支出カテゴリ | 収入カテゴリ |
|---|---|
| 食費・日用品・交通・交際費・娯楽・住居・光熱費・医療・教育・貯金・その他 | 給与・ボーナス・副業・投資・その他収入 |

### 7.4 合計計算ルール

- 支出合計 = 種類が「支出」のレコードの金額合計
- 収入合計 = 種類が「収入」のレコードの金額合計
- ネット残高 = 収入合計 − 支出合計

### 7.5 CSV入出力ルール概要

- 形式: `日付,種類,カテゴリ,金額,メモ`（ヘッダー行任意、4列または5列）
- 文字コード: 読込はUTF-8（BOM有無どちらも可）、書出はUTF-8（BOMなし）
- エクスポート: 日付昇順（同日付は登録順）で全件書き出し
- インポート: 既存データへの **追記**。行単位で検証し、正しい行のみ部分的に取り込む（部分成功方式）。重複チェックなし。

### 7.6 統計集計ルール概要

- カテゴリ別: カテゴリごとの合計金額・件数・全体に対する割合（%）を算出し、割合の降順で表示
- 年別／月別: 年（または年月）ごとの合計金額・件数を算出し、時系列の昇順で表示
- 表示対象が「支出」「収入」の場合は、表示直前にその種別でフィルタしてから集計する
- 表示対象が「合計」（年別・月別のみ）の場合は種別で絞らず、期間ごとに支出合計・収入合計を集計し、差額（収入合計 − 支出合計）を算出する。金額は支出・収入とも正の値で保持されるため、差額は減算で求める
- 上記いずれの集計も、事前に月範囲フィルタ（開始・終了を含む）で対象データを絞り込んでから行う

## 8. 非機能要件

| 分類 | 内容 |
|---|---|
| 永続化方式 | メモリ常駐＋CSVファイルによる手動エクスポート/インポート（DBなし） |
| データ保持期間 | アプリ起動中のみ（終了で消失、CSV保存分を除く） |
| 文字コード | UTF-8（BOM有無を許容して読込、書出はBOMなし） |
| 多言語対応 | 日本語UI固定（多言語化機構なし） |
| エラー通知 | `tkinter.messagebox`によるダイアログ表示（情報・警告・エラー） |
| ログ | 起動時未捕捉例外のみ標準出力に記録（通常操作時のログ出力機構はなし） |
| 同時実行 | マルチユーザー・マルチプロセス同期の考慮なし（単一プロセス・単一ウィンドウ前提） |
| パフォーマンス前提 | 個人利用規模のデータ件数を想定（大量データに対する性能要件は定義されていない） |

## 9. 制約事項

- カテゴリは一覧からの選択のみで、自由入力・カテゴリ追加はできない。
- 内部ID（Treeviewのiidにも使用）はアプリ実行中のみ有効な連番で、永続的なレコードIDではない。
- CSV再取込時の重複検知は行われない（同じファイルを2回取り込むと2重登録される）。
- 統計画面は開いた時点のスナップショットを表示するのみで、メイン画面のその後の変更を自動反映しない。
- 大量データ・同時編集・データベース連携など、業務システム的な要件は対象外（個人向け簡易ツールとしての設計）。
